# Форум гильдии Perfect World

Сайт для гильдии в игре Perfect World на Django: форум, приём заявок в гильдию с голосованием, аукцион за очки активности, кос-лист и уведомления.

## Возможности

- **Форум** — категории и подкатегории, темы, ответы с картинками. Доступ к разделам настраивается по группам пользователей и по флагу «только для авторизованных».
- **Профили** — аватар, класс персонажа, характеристики (HP, атака, защита, пробив и т. д.), TS3 ID, город, возраст.
- **Приём заявок** — кандидат заполняет анкету со скриншотами, администратор допускает её до голосования, члены гильдии голосуют «за» / «против» / «воздержался» с комментарием.
- **Аукцион** — лоты за очки активности. Ставка замораживает очки, при перебитой ставке очки возвращаются, победителю очки списываются после окончания лота.
- **Очки активности** — отдельная страница в админ-панели для быстрого начисления очков членам гильдии, сгруппированным по классам.
- **Кос-лист** — список враждебных гильдий и игроков.
- **Уведомления** — о голосах по заявке, решениях администратора, выигрыше на аукционе.
- **Настройки сайта** — название сайта и favicon меняются в админ-панели, без правки кода.

## Стек

Python 3.13+, Django 6, SQLite (поддержка PostgreSQL заготовлена в настройках), django-jazzmin (оформление админки), django-recaptcha, Pillow, gunicorn.

## Быстрый старт

```bash
git clone <адрес репозитория>
cd Perfect_World_guild_forum

# с uv
uv sync

# или через pip
python -m venv .venv
.venv\Scripts\activate        # Windows
source .venv/bin/activate     # Linux / macOS
pip install -r requirements.txt
```

Создайте файл `.env` в корне проекта (см. раздел ниже), затем:

```bash
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

Сайт откроется на http://127.0.0.1:8000/, админ-панель — на http://127.0.0.1:8000/admin/.

## Переменные окружения (`.env`)

| Переменная | Обязательна | Описание |
|---|---|---|
| `DEBUG` | — | `True` для локальной разработки. По умолчанию `False` |
| `DJANGO_SECRET_KEY` | при `DEBUG=False` | Секретный ключ Django |
| `ALLOWED_HOSTS` | при `DEBUG=False` | Домены через запятую |
| `DATABASE_URL` | — | Строка подключения к БД, например `postgres://user:pass@localhost:5432/forum`. По умолчанию SQLite |
| `USE_HTTPS` | — | `True`, когда на сервере настроен SSL: включает редирект на https и secure-куки |
| `RECAPTCHA_PUBLIC_KEY`, `RECAPTCHA_PRIVATE_KEY` | для регистрации | Ключи Google reCAPTCHA |
| `EMAIL_HOST` | для писем | SMTP-сервер. Если не задан, письма выводятся в консоль |
| `EMAIL_PORT` | — | По умолчанию `587` |
| `EMAIL_USE_TLS` / `EMAIL_USE_SSL` | — | По умолчанию `True` / `False` |
| `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD` | для писем | Логин и пароль SMTP |
| `DEFAULT_FROM_EMAIL` | — | Адрес отправителя |

Пример для локальной разработки:

```env
DEBUG=True
DJANGO_SECRET_KEY=любая-длинная-строка
```

## Первичная настройка в админ-панели

1. **Настройки сайта** — укажите название гильдии и загрузите favicon (`.ico` или `.png`).
2. **Группы** — создайте группу `Член гильдии`. Её участники голосуют по заявкам и попадают на страницу очков активности.
3. **Категории и подкатегории** форума. Специальные подкатегории отмечаются флагами:
   - «Это аукцион» — ведёт на страницу аукциона;
   - «Это приём заявок» — форма подачи заявки (скрыта от членов гильдии);
   - «Это просмотр заявок» — список заявок на голосовании (только для членов гильдии).

## Аукцион

После плановой даты окончания ставки на лот закрываются, а завершает аукцион администратор — в админ-панели на странице лота (можно выбрать победителя вручную) или действием «Завершить выбранные аукционы». Отмена аукциона возвращает все замороженные очки.

Завершить все просроченные лоты автоматически (с победителем — лидером ставок) можно командой, например по cron:

```bash
python manage.py check_auctions
```

## Деплой

```bash
python manage.py migrate
python manage.py collectstatic
gunicorn config.wsgi:application
```

- Исходники статики лежат в `static_src/`, `collectstatic` собирает их в `static/`. Веб-сервер (nginx) должен отдавать `static/` по адресу `/static/`.
- Загруженные файлы (аватары, скриншоты, favicon) лежат в `media/` и тоже отдаются веб-сервером по адресу `/media/`.
