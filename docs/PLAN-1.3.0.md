# Обновление 1.3.0: ивенты

Рабочая ветка: `update/1.3.0`. Предыдущие изменения уведомлений и инструкции проекта сохраняются в этой ветке. Версия приложения и релизный тег меняются отдельно при выпуске.

## Целевой сценарий

Администратор создаёт тип ивента и редактирует его постоянные отряды. Составы не пересоздаются к каждой дате. Для конкретной даты назначается проведение ивента с приглашением: игроки отвечают, а фактическое посещение учитывается отдельно через TeamSpeak. Страницы используют общую тему сайта.

## Этапы и коммиты

1. **Постоянные отряды.** Один постоянный состав на тип ивента; редактирование с проверками вместимости и повторного назначения игрока. Существующие составы сохраняются. Убирается необходимость отдельно создавать «Ивент» ради отрядов.
2. **Приглашения и явка по датам.** Создание проведения на дату, корректное состояние отправки, ответы приглашённых и просмотр фактического присутствия. Сохраняется интеграция TeamSpeak и однократное начисление очков.
3. **Общий интерфейс.** Список типов, постоянные составы, страницы приглашения и явки, история ответов — на общих элементах и переменных оформления.
4. **Проверка и документация.** Регрессионные тесты, изолированное локальное демо, визуальная проверка реальных страниц на десктопе и 320/390/430 px в обеих темах, обновление руководств.

Каждый этап завершается проверками и отдельным коммитом в стиле истории проекта. Публикация ветки и релиз не входят в эти этапы автоматически.

## Принятые ограничения

- Предварительный ответ «Буду» не считается подтверждённой явкой.
- Данные существующих приглашений, ответов и учёта присутствия сохраняются.
- Демо использует отдельную базу; контейнеры пользователя не перезапускаются для проверки интерфейса.
- Подтверждено владельцем: дата и рассылка назначаются вручную; составы редактируют администраторы и пользователи с правом управления отрядами.

## Результаты этапов

### Этап 1

Один постоянный состав на тип, безопасное объединение прежних дублей, редактирование отряда на сайте с проверкой прав, дублей и вместимости. Скрыты промежуточные разделы «Ивенты» и «Участники». Проверки: 47 тестов `events notifications demo`, согласованность миграций. Визуальная проверка новых страниц запланирована после общего оформления на этапе 4.

### Этап 2

Создание даты с отправкой или сохранением черновика; рассылка выполняется однократно и фиксирует места приглашённых в отрядах. Старые ошибочные даты отправки без получателей очищаются. Черновики доступны только управляющим, ответы закрываются после окончания; явка TeamSpeak показана отдельно от обещаний. Проверки: 83 теста `events notifications teamspeak demo`, согласованность миграций.

### Этап 3

Страницы списка, типа, ответа, явки, истории и редактирования используют общую тему; добавлены поиск участников и постраничный вывод. Завершённые приглашения в уведомлениях ведут к отчёту. Проверки: 53 теста `events notifications demo`, локальное демо на временной базе, 64 снимка восьми страниц в двух темах на 1440/320/390/430 px; автоматическая проверка переполнения и просмотр основных снимков. Контейнеры не перезапускались.

### Этап 4

Добавлен тест миграции со старой схемы: сохраняются отряды, лидеры, участники, примечания и отправленные приглашения, восстанавливаются отсутствующие постоянные составы. Черновики исключены из учёта и начислений TeamSpeak. Ответы сохраняются под блокировкой проведения; рассылка выполняется пакетно, с защитой от повторной отправки. Обновлены пользовательское и техническое руководства.

Итоговые проверки:

- `cd app && python manage.py test --noinput`: 238 тестов, успешно, один пропуск — настоящий gpg недоступен в локальном окружении.
- `cd tsbot && python -m unittest discover -s tests -t .`: 19 тестов, успешно.
- `manage.py check`, `makemigrations --check --dry-run`, `git diff --check`: без ошибок.
- Реальные страницы временного локального демо: восемь маршрутов, тёмная и светлая темы, 1440/320/390/430 px, синий акцент; 64 снимка, горизонтального переполнения нет. Основные снимки просмотрены.
- Через браузер пройдены редактирование отряда, поиск с сохранением выбора, смена ответа с комментарием, создание черновика и отправка. Для обычного участника проверены скрытие управляющих кнопок и серверный запрет редактирования.

База для проверок — временная SQLite, медиа — отдельный временный каталог. На физическом телефоне, реальном сервере TeamSpeak и PostgreSQL эти изменения не проверялись; контейнеры пользователя не обновлялись. Тег релиза и версия приложения не изменялись.
